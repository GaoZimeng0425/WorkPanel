# WorkPanel — 每日开工规划仪式（今日承诺 + 数据复盘）设计

**日期**：2026-06-01
**状态**：设计已确认，待写实现计划
**平台**：macOS 26.5，Swift 6（严格并发），SwiftUI + SwiftData

## 1. 目标

WorkPanel 已经很会「记录和整理」任务（捕获面板 + 看板/象限/今日/优先级 4 个透镜），但缺一个**计划仪式**：任务堆着，却没有「每天开工先规划、定期回顾」的固定动作，导致不知道今天到底该干哪几件。

本设计补上这个缺口，遵循用户选定的工作哲学：

- **方法论**：每日要事（MIT）+ 在制品（WIP）意识——每天开工时主动挑出今天要推进的「今日承诺」。
- **强制力**：**只记录、不干预**。工具永不拦截、不限量、不弹规则，靠**事后把事实反馈给你**来改变行为。
- **闭环**：开工规划产生承诺数据 → 工具静默记录承诺/完成/顺延 → 复盘把数据反映回来，让「只记录」有牙齿。

## 2. 范围

**做**：
- 开工规划流程（每天首次打开看板自动触发，可手动重进，可跳过）。
- 「今日承诺」概念：用户主动挑选的今日任务集，取代现有 deadline 驱动的「今日」透镜语义。
- 静默记录每日承诺历史（新增 `DayPlan` 模型）。
- 复盘透镜（第 5 个透镜）：本周承诺 vs 完成、顺延榜、超载天数。

**不做**（YAGNI，且与「只记录不干预」哲学冲突）：
- 任何硬性 WIP 上限 / 超额拦截 / 打断式弹窗。
- 每周回顾流程、目标/项目层级、时间块、趋势图表（属更重的方案 C，本期不做）。
- 图表库依赖——复盘用纯 SwiftUI 画简单条形/数字。

## 3. 数据模型

**只新增一个模型，不修改 `TodoTask`。** 今日承诺、本周承诺、顺延、超载等全部从 `DayPlan` 历史 + 任务已有的 `completedAt` 派生。

```swift
@Model final class DayPlan {
    var day: Date                  // 归一化到当天 00:00（Calendar.startOfDay）
    var committedTaskIDs: [UUID]   // 那天主动承诺要推进的任务

    init(day: Date, committedTaskIDs: [UUID] = []) { ... }
}
```

- 每个完成过开工规划的日子一条 `DayPlan`。`day` 唯一（按 startOfDay 归一化）。
- 「今天该干哪些」= 读今天那条 `DayPlan`，用 `committedTaskIDs` 在内存里过滤任务集合（任务数小，无需复杂 predicate）。
- `committedTaskIDs` 只存 ID，不建 SwiftData 关系，避免删除任务时的级联复杂度；渲染时按 ID 取任务，取不到（已删除）就跳过。

## 5. 开工规划流程

- **触发**：用 `@AppStorage` 存「上次规划日」。每天第一次打开看板时，若上次规划日 ≠ 今天，自动进入 `PlanningView`。另在「今日」透镜头部放「规划今天」按钮，可手动重进。
- **候选排序**：逾期 + 今天到期的任务排最前（作为「建议」高亮），其余活动（未完成、未 snooze）任务按优先级跟随。
- **交互**：点选任务加入「今日承诺」，顶部实时显示「已承诺 N 件」。**不限数量、不拦截、无打断式提示**。
- **确认**：写入/更新今天的 `DayPlan.committedTaskIDs`。
- **可跳过**：永不强制。跳过则今天无 `DayPlan`，今日透镜显示「还没规划今天」+ 一键开工 CTA。
- **跨天承诺顺延**：开工规划时，昨天承诺过但仍未完成的任务，在候选列表里默认预选/置顶提示，用户决定是否继续承诺（继续承诺即产生「顺延」信号）。

## 6. 今日透镜改造

- 由「逾期 + 今日到期」改为显示**今天 `DayPlan` 里的承诺任务**。
- 头部显示「承诺 X · 完成 Y」。
- 对「今天到期但未纳入承诺」的任务，底部给一句克制提示：「另有 N 件今天到期未纳入」——只提示、不强加。
- 空态（今天还没规划）：显示开工规划 CTA。

## 7. 复盘透镜（`ReviewLensView`）

第 5 个透镜，与现有透镜风格一致，只读，纯 SwiftUI 画简单条形/数字，无图表库。默认展示本周三块：

1. **承诺 vs 完成**：每天一对数字/小条——当天承诺 N 件、其中当天完成 M 件。
2. **顺延榜**：被承诺 ≥2 天却仍未做完的任务，按顺延天数倒序。
3. **超载天数**：本周「承诺 − 完成 ≥ 阈值」的天数。

## 8. 统计口径（纯函数，便于测试）

全部从 `DayPlan` 集合 + 任务的 `completedAt` 派生：

- **承诺数（某日）** = 那条 `DayPlan.committedTaskIDs.count`。
- **完成数（某日）** = 该日承诺的任务里，`completedAt` 落在当天的数量。
- **顺延天数（某任务）** = 它出现在多少条 `DayPlan` 里、且对应日均未完成。
- **超载日** = `承诺数 − 完成数 ≥ overloadThreshold` 的日子。`overloadThreshold` 默认 = 3（保守默认，后续可调）。

## 9. 已定默认（可后续调整）

- 复盘做成**第 5 个透镜**（而非菜单栏单独入口）。
- 超载阈值默认 = 3。
- 跨天触发判定基于本地日历自然日。

## 10. 测试策略

对齐既有习惯（拖拽/交互类 UI 用 store 单测覆盖，UI 测试只做冒烟）：

- **统计纯函数单测**（重点）：承诺/完成/顺延/超载各口径、跨天边界、空数据 fixture。用内存 `ModelContainer`。
- **开工规划「自动触发判定」单测**：跨天比对函数（上次规划日 ≠ 今天）。
- **`DayPlan` 读写单测**：toggle 承诺、同一天去重、删除任务后 ID 取不到的容错。
- 规划面板点选交互、复盘视图渲染 → 手动验证 / UI 冒烟。
